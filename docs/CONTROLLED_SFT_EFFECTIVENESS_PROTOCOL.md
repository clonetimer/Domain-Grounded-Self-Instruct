# DGSI controlled SFT effectiveness protocol (pre-registration draft)

## Objective

Test whether DGSI improves the LLM's **second-stage engineering diagnosis** from upstream ML results, diagnostic logs, spacecraft/mission context and retrieved historical experience.

The study must establish diagnostic utility, not merely valid JSON, larger data volume, or stylistic similarity to a reference report.

## Data tracks and claims

Report each source class separately:

- `REAL_GOLD`: independently adjudicated real/de-identified engineering cases with authorized source provenance and complete LLM-visible input.
- `LITERATURE_DERIVED_SYNTHETIC`: scenario packets constructed from public L0 fact cards with field-level synthetic provenance.
- `SYNTHETIC_TEST_ONLY`: validator/adapter fixtures; not counted as training examples or Gold.
- `KNOWLEDGE_SOURCE_NOT_EVENT`: manuals, expert-system demonstrations or technical knowledge; not counted as fault episodes.

The current three-packet pilot is L1, review-required and synthetic. It is not yet a training set. Do not report it as three real incidents.

## Experimental arms

| Arm | Training | Inference-time history |
|---|---|---|
| A — Base | No DGSI SFT | Off |
| B — Generic SFT | Matched-size general Self-Instruct data | Off |
| C — DGSI synthetic | Literature-derived synthetic DGSI SFT only | Off |
| D — DGSI real Gold | Independently approved real Gold only, when available | Off |
| E — DGSI + Context | Same DGSI model/checkpoint as C or D | On, with time-safe retrieved history |

Do not mix real Gold and synthetic examples into one unlabelled aggregate. If a combined training arm is later tested, report real/synthetic ratios and ablations explicitly.

## Dataset and split controls

1. Split by `event_family_id`, not individual rows or paraphrases.
2. Keep all variants from one literature report/event family in a single split.
3. Keep the holdout source reports and incident families inaccessible to prompt construction and synthetic generation.
4. Do not use one source report to generate training scenarios and then evaluate on a different paraphrase of the same report as if independent.
5. For Context experiments, freeze the retrieval corpus at the evaluation cutoff; block future confirmations and same-incident-family retrieval.
6. Match training data volume and optimization budget across arms where feasible; report deviations.
7. Keep L0 source cards, synthetic generation recipes and private expert targets out of the user prompt unless explicitly intended as evidence.

## Evaluation set

Use two separately reported evaluation strata:

### Synthetic controlled holdout
- Held-out literature event families, not used to author training tasks.
- Includes candidate/confirmed/ambiguous causes, measurement-chain confounders, common-cause cross-subsystem effects, rejected historical explanations, no-history and conflicting-history cases.
- Synthetic upstream ML findings and logs are clearly marked and generated by a frozen recipe.

### Real engineering holdout
- Only authorized, de-identified cases with independent expert adjudication.
- Must not share incident family, spacecraft episode or upstream ML run with training data.
- If no such cases are available, report the real-holdout arm as NOT_RUN. Do not substitute synthetic cases and call them real.

## Metrics

Primary metrics:
1. Fault-source localization: exact/component-family accuracy and expert-rated correctness.
2. Affected-component identification: precision/recall or expert-rated correctness, separate from fault source.
3. Evidence consistency: fraction of claims supported by cited input evidence; dangling/misattributed evidence rate.
4. Uncertainty calibration: appropriate CONFIRMED / MOST_LIKELY / CANDIDATE / UNRESOLVED decisions; Brier/ECE only where a defensible probability target exists.
5. Disposal fidelity: correct distinction between executed, planned, recommended and not recorded; fabricated historical-action rate must be zero.
6. Historical-context use: correct transfer, non-transfer and rejection of unresolved/rejected/incompatible/future history.
7. Abstention and insufficiency: correct refusal to over-localize when evidence is insufficient.

Secondary metrics:
- Report completeness and readability;
- cross-subsystem affected-component coverage;
- consistency between structured output and report text;
- inference latency and token cost (if measured).

Do not treat ROUGE/BLEU or similarity to one expert wording as primary diagnostic correctness.

## Human evaluation

Use at least two independent domain reviewers for the final comparison where feasible. Blind reviewers to model arm and data track. Score:
- fault correctness;
- evidence relevance and traceability;
- phenomenon/causal distinction;
- uncertainty appropriateness;
- affected-component correctness;
- disposal/action fidelity;
- engineering readability and actionability.

Resolve disagreements using a documented adjudication process. Reviewer identity and permissions are verified outside model-facing packets.

## Success and stop criteria

Before training, freeze:
- evaluation cases and event-family split;
- metric definitions and scoring rubric;
- prompts and decoding settings;
- model checkpoint and training budget;
- retrieval corpus snapshot and cutoff policy.

DGSI value is supported only if DGSI arms improve pre-registered primary metrics over Base and Generic SFT on independent holdout without increasing false certainty, evidence hallucination or fabricated disposal. Context arm E must be compared with the same model without retrieved history to isolate retrieval contribution.

If gains appear only on literature-derived synthetic holdout but not real engineering holdout, state that limitation; do not claim demonstrated operational diagnostic improvement.
