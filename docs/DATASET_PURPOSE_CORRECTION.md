# DGSI 数据集目标纠偏：从遥测诊断转为诊断结果与上下文研判

## 决策

DGSI 的核心 SFT 任务不是让 LLM 从原始遥测推断故障，而是让 LLM 基于上游算法已经形成的诊断结果、诊断日志、历史案例和航天器运行上下文，完成综合研判、证据解释、经验复用、冲突处理及后续核查建议。

职责边界：

- ML / 统计诊断：读取遥测，完成异常检测、故障候选识别、时间定位、特征/残差计算和部件定位。
- LLM：读取 ML 诊断输出及其证据摘要、诊断日志、历史案例、构型与任务上下文、知识证据，完成二次研判和报告组织。
- 专家/工程闭环：确认、修正或驳回研判，形成可追溯经验记录。

LLM 输入默认不包含原始遥测。必要时可有受控证据引用或上游分析产物 ID，但不能要求 LLM 重新执行时序信号诊断。

## 数据集实例层级

每个 SFT 样本由五部分构成：

1. **Machine diagnosis result**：算法/模型名称与版本、分析范围、候选故障、定位结果、评分语义、证据 ID、算法局限。
2. **Diagnostic logs**：告警、事件、操作员记录、工程分析、维护记录、历史处置记录及时间顺序。
3. **Spacecraft and operational context**：型号/构型、分系统组成、任务阶段、工作模式、近期操作、环境条件和约束。
4. **Historical experience and knowledge**：相似案例、既往结论及其确认状态、适用条件、文献/知识图谱证据定位。
5. **Expert-reviewed target**：研判结论、对机器诊断结果的解释、故障源与受影响对象区分、支持/反对证据、不确定性、下一步核查和结构化报告。

## 任务类型

- `diagnostic_synthesis`：综合算法结果与上下文形成研判。
- `historical_case_reuse`：判断历史经验的可迁移性，不机械套用旧结论。
- `conflict_reconciliation`：处理算法、日志、历史记录之间的冲突。
- `evidence_sufficiency`：判断现有证据能否支持确认故障。
- `next_step_recommendation`：提出能够区分候选假设的下一步检查。
- `handover_summary`：生成面向值班人员/工程师的交接摘要。

## 输入禁止项与保护边界

- 不内嵌原始遥测数组、波形或完整高频时序数据。
- 不把 ML 分数默认解释为概率；必须保留 score semantics、校准状态和模型版本。
- 不把算法候选写成已经确诊的故障。
- 不把“受影响部件”自动当作“故障源部件”。
- 不将历史未确认案例转化为当前确诊依据。
- 不允许将仿真注入真值、测试标签或答案侧信息放入用户输入。
- 不要求 LLM 补造缺失的算法结果、事件记录或物理证据。

## 目标输出

- 研判处置状态：接受、附条件接受、要求补充分析、证据冲突、上下文不足、未见故障。
- 对机器诊断结果的解释及其局限。
- 故障源候选与受影响部件（分别表示）。
- 支持证据、反证、缺失信息。
- 历史经验的相关性和迁移限制。
- 不确定性及原因。
- 下一步核查建议和优先级。
- 面向工程人员的结构化诊断报告。

## 训练数据分层

- **Gold supervised**：由有权限的领域专家审核通过的目标答案。
- **Silver reviewed**：机器生成且结构检查通过，但尚未专家批准；只能用于开发分析，不进入正式 SFT。
- **Rejected**：输入缺少关键上下文、来源不明、答案超出证据或发生标签泄漏。

## 划分单位

以诊断事件/故障 episode、历史案例族、航天器构型和来源文档群组为单位进行分组隔离。来自同一事件的多份日志、不同摘要、相似问法和重复报告必须留在同一 split。测试集不得参与提示词、Skill、检索规则或答案修订。

## 评价目标

评价 LLM 的二次研判能力，而不是重新评价 ML 遥测检测能力：

- 机器诊断结果解释正确性；
- 证据引用准确性与覆盖率；
- 故障源/受影响对象区分；
- 历史经验适用性判断；
- 冲突识别与处理；
- 证据不足时的拒绝/保留判断；
- 下一步核查建议的可执行性；
- 报告完整性和工程可读性。

最终模型对照应比较基础 LLM、普通 Self-Instruct SFT、DGSI 领域上下文 SFT；在完全相同的诊断结果包和测试事件上评估。
