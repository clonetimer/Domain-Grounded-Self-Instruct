# DGSI v0.2.0 收敛交付记录

## 交付结论与范围

本轮按用户授权执行三个收敛阶段：冻结可用入口、完成代表性端到端验收、完成四案例五种构建方法的实际生成与 GPT 辅助评审。没有把缺少人类专家变成工具交付的阻塞项，也没有生成虚假的人类审核结论。

统一入口为 `python scripts/run_dgsi_skill.py`，完整使用步骤见 [中文复现与复用说明](../skills/dgsi-simulation-to-sft/references/CLOSEOUT_QUICKSTART.md)。输出包括真实保存的模型生成候选、三消息开发 JSONL、逐条 GPT 评分、来源与修订绑定，而不是只有空白表和审查流程。

这次交付关闭的是 **可复用 Skill 与开发示例的工程收敛阶段**。项目的正式高质量卫星故障诊断 SFT 产品目标仍需真实来源、适用权利和正式数据准入来实现；当前真实 Gold、训练授权和已执行微调仍均为零。用户授权 GPT 替代当前预审，不能凭此把合成输入变成真实飞行记录。

## 阶段一：固定一个版本和入口

- 工具版本：`0.2.0`，基于已核验的 #184 head `d7e151caee664831d6535cf0359f8686cd6ce532`。
- `prepare`：检查 L0/L1 来源绑定，生成只有 system/user 的新生成请求；原 packet 不修改，参考目标和 internal_review 不入模型输入。
- `demo`：离线验证并重放本次冻结的 4×5 实验、原始评分和单独的交付修订；不调用模型。
- 提示、schema、原始生成、盲评输入、评分、来源生成字段及清晰的中文操作说明全部随包交付。
- 本轮未合并 main，没有访问或上传用户私有案例日志，没有调用外部付费模型 API，没有启动训练。

现有辅助命令保留兼容性。后续以用户材料的实际复用问题为依据修复，不再因未完成外部材料而持续新增流程。

## 阶段二：代表性产品验收

独立工程检查在干净解压的原 toolkit 中执行了 21 次 CLI 命令，全部得到预期结果，含预期拒绝覆盖已有输出的情形。验证覆盖：

| 代表材料 | 覆盖的实际流程 | 结果边界 |
|---|---|---|
| 诊断综合合成任务 | 来源绑定、review kit、空白审核回流、模型预览 | 流程可执行，不把空白表当审核通过 |
| 历史复用合成任务 | 同上，并检查历史迁移字段 | 历史不能投票确认当前根因 |
| 证据充分性任务 | 来源约束和不充分证据的正式输出 | 不把部件名或上游候选变成确诊 |
| 冲突协调任务 | 载波/监测量、对照范围和证据角色 | 正式目标保持局部结论及不确定性 |
| 合成仿真收据 | 本地 8/8 文件哈希匹配 | 实际仿真运行 0；物理有效性仍为 false |

检查在禁用网络连接的进程中执行，网络连接尝试为零；同一环境的两次旧版工具包构建字节一致。此验收是已有候选的端到端工程回放；新生成证据由下面阶段三提供，二者不混称。

新统一入口还实际处理了完整 21 个任务的原有 cohort，并阻断 3 条缺可信时间来源的历史内容；包内的四任务子集输出 4 条请求、阻断 1 条历史。原有 21 个任务仍属 9 个事件族。方法比较只选其中 4 个案例，不能把 20 次生成计为 20 个独立事件。

代码复核发现并修复了：有效指令或方法归属改变却沿用旧评分、缺失实验单元却可重放成功、空白字符导致 reviewer token 误判为两人。新回归测试覆盖这些实际缺陷以及重放哈希破坏、输出不覆盖和从任意工作目录启动。

## 阶段三：已执行的 4×5 构建比较

四个输入分别覆盖诊断综合、历史经验拒绝迁移、冲突协调、证据充分性。生成器统一为本会话声明的 GPT-6 Astra Pro；每种方法使用一个新的生成会话，按相同顺序处理四个案例，不读取其他方法答案。精确 API 模型 ID、服务修订版本和实际 token 用量不可见，均不编造。

两个新的评审会话配置为 `gpt-6.2-sol`，分别逐条评阅 20 个候选，每条十维、0–2 分。两个会话彼此不见评分，均不见方法标签。它们是同一评审模型的两个独立会话，误差可能相关；它们不是两个人类专家。评分只衡量对所提供合成场景的忠实度和开发可用性，未独立验证文献全文或物理模型。

共 20 个原始候选、40 份评分记录、400 个维度评分；11 条共同接受，9 条需要修订，8 条存在评分/建议/重大错误列表中至少一种分歧。无人类专家评分。关键失败为零是这两次 GPT 检查的观测，不是未检出错误即证明事实正确。

评分维度保持统一：source_fidelity、phenomenon_analysis、ml_interpretation、fault_source、affected_components、evidence_fidelity、uncertainty、disposal_fidelity、historical_context_transfer、engineering_actionability。重大错误使用冻结的八个代码；普通修订发现另有固定位置和证据引用。

本次**没有证明 DGSI 优于其他方法**。四例中分数接近、基线接受同样严格的场景边界和输出格式、样本很小，而且没有独立真实 holdout 与下游微调。因此这是一份可检查的构建流程实验，不能宣称通用方法排名或 SOTA 优势。

### 可复用的 DGSI 交付小集

DGSI 的 4 条原始候选中，3 条被两评审接受；冲突协调案例需要明确活动发射路径对齐、窗口内未切换，以及监测摘要与 ML 推断各自的证据角色。

仅对该条制作 `REVIEW-ITEM-019-R1`，原始候选、原评分和比较表不变。两评审分别对新哈希版本复评，均为 ACCEPT、20/20、无重大错误。此修订与 3 条原始接受候选组成 **4 条 GPT 双评接受的开发交付小集**，通过 `dgsi_curated_preview_messages.jsonl` 输出。另有 1 次修订、2 份复评记录、20 个维度评分，单独统计，不增加独立事件数，也不提高原始方法比较分数。

## 可核验记录及复现边界

原始文件、逐条结果、方法映射、来源 packet 哈希和生成字段均在 `evaluation/closeout_20261119/`。`replay_manifest.json` 绑定文件内容；每个 GPT 评分同时绑定输入、正式目标和包含有效指令/方法归属的候选哈希。任一内容变更，旧评分不能继续使用。

会话工具不提供严格 token 限额或种子控制；2048 token/条只是原计划请求上限，不是实测或硬约束。统一模型与案例数量不等同于严格等计算预算。用户可逐字重放现有结果，或按冻结提示重新生成并重新评分；后者不保证逐字相同。

原论文方法来源：

- [Self-Instruct](https://aclanthology.org/2023.acl-long.754/)：生成与筛选任务/实例；本次只执行小规模聊天适配。
- [WizardLM / Evol-Instruct](https://proceedings.iclr.cc/paper_files/paper/2024/hash/82eec786fdfbbfa53450c5feb7d1ac92-Abstract-Conference.html)：演化指令；本次每例一次约束复杂化。
- [Magpie](https://proceedings.iclr.cc/paper_files/paper/2025/hash/be06e3802e9411381feece79b4d960c1-Abstract-Conference.html)：原生模板 pre-query 生成；本次只能仿写用户查询，没有声称执行原生过程。
- [Auto-Instruct](https://aclanthology.org/2023.findings-emnlp.659/)：候选指令与训练过的排序器；本次使用生成模型自评排序，不等同于论文的排序器。
